# Counter run of the proposed method (2026-11-17)

Command: `run.sh` in this directory, at the commit in `environment.txt`. Arm: IncAdaTaSPM-StaticPreLarge
(phi = 0.5, eta = 0.5, lazy insertion, Score = 1), the seven stream configurations of the experiments.

The engine is a counted copy of `src/main/java/com/adaptive/itr/spm/IncAdaTaSPM.java`, generated by
`tools/counters/make_counted_engine.py` (source and copy hashes in `generated_copy.txt`). The measured
benchmark jar is not changed. Added counters, one row per batch in `<dataset>.csv`:

* `proj_initial`, `proj_walk_increment`, `proj_rescan`, `proj_promotion`, `proj_ancestor`: projections by
  source (initial mine; batch walk on the increment; rescan expansion, stub promotion and passing through an
  ancestor on the way to a marked node, all three on the full D_T). Their sum equals `projections` in every row.
* `max_rescans_one_node`: largest number of rescans of one tracked node since it was created, so far.

Check: the counters that the measured engine also records (patterns, rescans, rescan_inserts, promotions,
projections, live_nodes, tombstones, stubs) equal those of the live runs of the measurement machine
(`results/stream-bench/PC-THAI/*__IncAdaTaSPM-StaticPreLarge__live.csv`) in every batch: 7 datasets x 101
batches compared, 0 differences (`summary.txt`). Fault injection of that comparison: a copy whose rescan mark
uses `>` instead of `>=` gives 174 differences on BMS1.
